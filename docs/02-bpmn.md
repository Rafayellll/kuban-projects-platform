# 02. BPMN-диаграммы ключевых процессов

> Нотация BPMN 2.0 (упрощённая, в Mermaid `flowchart`).
> Все диаграммы рендерятся в GitHub, на сайте Mermaid Live Editor и в любом BPMN-просмотрщике, импортирующем Mermaid.
> Дополнительно PNG-версии лежат в `docs/diagrams/`.

Используемые элементы:

| Обозначение | BPMN | Mermaid |
|---|---|---|
| Старт / Конец | Event (Start / End) | `((Старт))` / `((Конец))` |
| Задача (Task) | Прямоугольник | `[Задача]` |
| Развилка (Gateway) | Ромб | `{Условие?}` |
| Подпроцесс | Прямоугольник с «+» | `[[Подпроцесс]]` |
| AI-сервис | Системная задача | `[(AI: ...)]` |
| Дорожка (Swimlane) | Pool / Lane | `subgraph` |

## 2.1. Процесс «Студент → проект → завершение»

Главный сквозной процесс блока **B**. Показывает путь молодого человека от регистрации до получения подтверждённого опыта.

```mermaid
flowchart LR
    subgraph S["Дорожка: Студент"]
        A((Старт)) --> A1[Регистрация / логин через ВК / Госуслуги]
        A1 --> A2[Заполнение цифрового профиля:<br/>вуз, курс, интересы, навыки]
        A2 --> A3[(AI-профориентатор:<br/>анкета + чат)]
        A3 --> A4[Получение карьерной траектории<br/>и подборки направлений]
        A4 --> A5[Просмотр ленты проектов]
    end

    subgraph M["AI-сервисы"]
        AI1[(AI-матчинг:<br/>профиль ↔ проект)]
        AI2[(AI-куратор:<br/>советы, дедлайны)]
        AI3[(AI-ревью:<br/>оценка артефактов)]
    end

    subgraph C["Дорожка: Компания / Ментор"]
        C1[Публикация кейса]
        C2{Заявка студента?}
        C3[Просмотр кандидатов + AI-скоринг]
        C4[Приглашение в команду]
        C5[Постановка задач, чек-поинты]
        C6[Финальное ревью]
        C7[Решение: оффер / резерв / отказ]
    end

    A5 --> AI1
    AI1 --> A6[Топ-5 подходящих проектов]
    A6 --> A7[Подача заявки]
    A7 --> C2
    C1 -.-> AI1
    C2 -->|Да| C3
    C2 -->|Нет| A5
    C3 --> C4
    C4 --> A8[Принятие приглашения]
    A8 --> A9[[Выполнение проекта<br/>2–8 недель]]
    A9 --> AI2
    AI2 --> A9
    A9 --> A10[Загрузка артефактов / отчёта]
    A10 --> AI3
    AI3 --> C6
    C5 --> C6
    C6 --> C7
    C7 --> A11[Цифровой бейдж + запись в портфолио]
    A11 --> Z((Конец))
```

## 2.2. Процесс «Компания: публикация кейса и подбор команды»

```mermaid
flowchart TD
    K((Старт)) --> K1[Регистрация компании / верификация ИНН]
    K1 --> K2[Заполнение карточки компании:<br/>ценности, культура, направления]
    K2 --> K3[Создание кейса:<br/>описание, сроки, навыки, оплата]
    K3 --> K4{Кейс корректен?}
    K4 -->|Нет, ошибки| K3
    K4 -->|Да| K5[(AI-валидатор:<br/>проверка постановки)]
    K5 --> K6[Модерация платформы]
    K6 --> K7{Одобрено?}
    K7 -->|Нет| K3
    K7 -->|Да| K8[Публикация в ленте]
    K8 --> K9[(AI-таргетинг:<br/>уведомления подходящим студентам)]
    K9 --> K10[Сбор заявок]
    K10 --> K11[(AI-скоринг:<br/>рейтинг кандидатов)]
    K11 --> K12[Просмотр шортлиста]
    K12 --> K13{Достаточно команды?}
    K13 -->|Нет| K9
    K13 -->|Да| K14[Формирование команды<br/>и kick-off]
    K14 --> KE((Кейс запущен))
```

## 2.3. Процесс «AI-матчинг студента и проекта»

> Сценарий ИИ № 1 — основа продуктовой ценности.

```mermaid
flowchart LR
    U[Студент] -->|profile_vector| EMB1[(Эмбеддинг профиля:<br/>навыки + интересы + история)]
    P[Проект] -->|project_vector| EMB2[(Эмбеддинг кейса:<br/>описание + требования)]
    EMB1 --> V[(pgvector / Qdrant)]
    EMB2 --> V
    V --> RANK[(AI-ранжирование:<br/>cosine + бизнес-правила)]
    RANK --> FILT[Фильтр:<br/>город, формат,<br/>уровень, оплата]
    FILT --> RES[Топ-N рекомендаций]
    RES --> EXP[(LLM:<br/>«почему именно этот проект»)]
    EXP --> UI[Карточки в UI<br/>с объяснением]
```

**Что под капотом:**

1. **Embeddings:** `sentence-transformers` (или e5-large) поверх описаний.
2. **Хранилище:** `pgvector` в основной БД PostgreSQL.
3. **Ранжирование:** cosine similarity × бизнес-веса (приоритет региона КК, доступность по времени, оплата).
4. **Объяснимость:** мини-промпт к LLM («Объясни студенту, почему этот проект ему подходит, на основе совпавших навыков»).

## 2.4. Процесс «AI-куратор сопровождает студента»

> Сценарий ИИ № 2 — удержание и завершаемость.

```mermaid
flowchart LR
    START((Студент<br/>в проекте)) --> D1[(Daily-пинг:<br/>прогресс / блокеры)]
    D1 --> R1{Есть блокер?}
    R1 -->|Да| AICH[(AI-куратор LLM:<br/>декомпозиция,<br/>ссылки на ресурсы)]
    AICH --> R2{Решено?}
    R2 -->|Нет| ESC[Эскалация ментору]
    R2 -->|Да| D1
    R1 -->|Нет| D2{Дедлайн<br/>скоро?}
    D2 -->|Да| REM[Напоминание + чек-лист]
    D2 -->|Нет| D1
    REM --> D1
    ESC --> ME[Ментор отвечает]
    ME --> D1
    D1 --> FIN[Финал проекта]
```

## 2.5. Процесс «AI-профориентатор для новичков»

> Сценарий ИИ № 3 — точка входа.

```mermaid
flowchart TD
    N((Новый пользователь)) --> Q1[Короткий онбординг:<br/>5–7 вопросов о себе]
    Q1 --> AI[(AI-профориентатор LLM:<br/>смешанный диалог + тесты)]
    AI --> Q2[Студент задаёт вопросы<br/>«Кем я могу стать?»]
    Q2 --> AI
    AI --> REC1[Подборка направлений:<br/>IT, маркетинг, AgroTech, FinTech…]
    REC1 --> REC2[Связанные компании Краснодарского края]
    REC2 --> REC3[Подборка экскурсий + проектов]
    REC3 --> SAVE[Сохранение в трек<br/>«моя траектория»]
    SAVE --> END((Готово))
```

## 2.6. Процесс «Командная работа над проектом»

```mermaid
flowchart LR
    KO[Kick-off] --> SP[Sprint planning<br/>2 недели]
    SP --> TASK[Задачи в трекере]
    TASK --> DAILY[Daily-апдейт]
    DAILY --> MENT[Чек-поинт с ментором<br/>каждую неделю]
    MENT -->|нужна помощь| AICUR[(AI-куратор)]
    MENT --> REV{Спринт ок?}
    REV -->|Нет| SP
    REV -->|Да| ART[Артефакт спринта]
    ART --> END{Проект завершён?}
    END -->|Нет| SP
    END -->|Да| DEMO[Демо-день<br/>для компании]
    DEMO --> EVAL[Оценка результата + бейдж]
```

## 2.7. Сквозная карта взаимодействий ролей

```mermaid
flowchart TB
    subgraph Student["👩‍🎓 Студент"]
        s1[Профиль]
        s2[Подача заявки]
        s3[Выполнение проекта]
        s4[Получение бейджа]
    end
    subgraph Company["🏢 Компания"]
        c1[Регистрация]
        c2[Публикация кейса]
        c3[Подбор команды]
        c4[Оценка результата]
    end
    subgraph Mentor["🧑‍🏫 Ментор"]
        m1[Подтверждение роли]
        m2[Сопровождение]
        m3[Ревью]
    end
    subgraph Univ["🎓 Вуз / СПО"]
        u1[Подключение программ]
        u2[Зачёт практики]
    end
    subgraph Region["🏛 Регион"]
        r1[Аналитика<br/>кадрового резерва]
    end
    subgraph AI["🤖 AI-ядро"]
        ai1[Профориентатор]
        ai2[Матчинг]
        ai3[Куратор]
        ai4[Скоринг]
    end

    s1 --> ai1
    s1 --> ai2
    c2 --> ai2
    ai2 --> s2
    s2 --> c3
    c3 --> s3
    s3 --> m2
    m2 --> ai3
    s3 --> m3
    m3 --> c4
    c4 --> s4
    s4 --> u2
    u1 --> Student
    Region <-- agg --> AI
    Region <-- analytics --> Company
```

## 2.8. Замечания по реализации BPMN

- В MVP реализуются процессы **2.1, 2.2, 2.3, 2.5**.
- Процесс **2.4 (AI-куратор)** — частично (только чат + напоминания).
- Процессы **2.6, 2.7** — описаны как контракт между микросервисами; ниже см. файл `03-architecture.md`.
